# US006 — Object-Oriented Design (OOD)

*As a developer, I want to translate the object-oriented analysis into concrete design
decisions, so that implementation follows a consistent, justified architecture rather than
ad-hoc choices made while coding.*

## Acceptance Criteria

- Architecture Decision Records (ADRs) produced for each significant design choice, covering
  at minimum: how proactive maintenance warnings are generated, API style, layer/model
  separation, dependency direction (ports & adapters), the maintenance due-date detection
  strategy, and use-case orchestration
- Each ADR states the decision, context, rationale, and any rejected alternative / trade-off
- GoF / GRASP patterns in use are named and mapped to where they apply
- Design-only types (not yet scaffolded) are listed so backend scaffolding has a checklist
- Recorded in `docs/OOD/design-decisions.md`, referenced from this story
